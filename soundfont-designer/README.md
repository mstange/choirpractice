# Soundfont Designer

A web page for designing an instrument for the choir app ([`../site`](../site)), synthesized into a SoundFont file, while listening to it in the choir app's pieces.

MS Basic's instruments are a poor fit for following a part: the piano has a clear attack but dies away during long notes, and Choir Aahs sustains but has almost no attack. Neither follows a crescendo during a held note, because MuseScore exports the dynamics, hairpins included, as CC2 (breath controller), which no default SF2 modulator responds to. The velocity only says how loud a note starts.

The designed instrument has two layers on every note:

- **Tone:** a looped spectrum of harmonics, sustained for as long as the note lasts, whose loudness and brightness follow CC2 during the note.
- **Attack:** a short transient of decaying partials and a noise burst, like a plucked or struck string, which marks where each note starts and follows the velocity.

## Running it

```sh
npm install
npm run dev
```

`npm run dev` serves the page at http://localhost:5288/, a port other than the choir app's, so that the browser doesn't run the choir app's service worker on it. The choir app (`../site`) needs its own `npm install` too: the page plays with its synthesizer.

The page plays the pieces that the choir app knows: the demo, and the seasons that the choir app opened before, which it keeps in `localStorage`. Deployed at `choirpractice.app/soundfont-designer/`, the page shares the choir app's `localStorage`, and fetches from the same media host (`VITE_MEDIA_BASE`). With `npm run dev`, it also offers all seasons in `../media` (or the directory that `MEDIA` names: `MEDIA=/path/to/media npm run dev`), which it serves at `media/`. `npm run build` in `../site` builds the page into `site/build/soundfont-designer/`, and `npm run preview` there serves it at `/soundfont-designer/`, next to the choir app. It needs the pieces' `piece.json` and `score.mid`, and `media/soundfont/` for the other instruments.

- `npm test` builds the default patch, writes it as SF2 and SF3, reads it back and renders it with spessasynth, and checks what the file does (see `scripts/test-bank.ts`).
- `node scripts/spectrum.ts [--match] [preset or patch JSON] [keys]` compares the sustain of MS Basic's Choir Aahs with a patch's, as spessasynth renders them: per harmonic its level, the noise beside it and its spread in cents, and how a strong harmonic moves over time. With `--match`, it first matches the patch's contour to Choir Aahs, and measures how near that brought it.
- `npm run check` type-checks, `npm run format` formats with Prettier.

## Using it

- **Listening:** the bar at the top plays a piece with its vocal parts on the designed instrument, or on one of MS Basic's to compare. Focus brings one part forward, as in the choir app, and the loop repeats measures. The timeline shows the vocal parts' notes and, as a white line, the CC2 of the focused part (or the first). Space plays and pauses.
- **Keyboard:** the keyboard at the bottom, or the computer's keys from A (Z and X change the octave), plays the designed instrument, starting with CC2 at the velocity. With Swell, CC2 rises to 127 and back while a key is held. With Latch, keys stay down until pressed again, and sound anew whenever the instrument changes, so that a held chord can be listened to while editing. The last key played is the preview key of the plots.
- **Editing:** every change rebuilds the instrument in a worker, and the next notes play the new version, while playing too. Notes that sound go on with the old one. A rebuild of all samples takes about 200 ms; changing only envelopes, modulators or levels reuses the samples.
- **Vowel and spectral contour:** the vowel is the sung vowel's resonances; the contour is the rest of the timbre, one for E2, one for A#3 and one for E5, mixed on the keys in between. Draw on any, or let Match fit all three to the sustain of one of MS Basic's instruments, around the vowel that is picked; then picking another vowel keeps the rest of the timbre. Both change the timbre, not the loudness.
- **Note plot:** the level of the preview key over time, as the synthesizer renders the built file: at MuseScore's p, mf and ff velocities, and swelling from p to ff, released at the dashed line.
- **Saving:** the patch being edited is kept in `localStorage`. Save keeps it by name, Export JSON and Import JSON move patches between browsers. Start from offers a few patches to begin with (`src/lib/presets.ts`). The page starts with MS Basic Aahs, which is as near MS Basic's Choir Aahs as the parameters come: on E2, C4 and C5 its harmonics are 3.8, 3.5 and 4.3 dB (rms) from Choir Aahs's, as wide (25, 24, 25 cents against 30, 24, 25), its level within 0.3 dB on average and its velocity response within 0.1 dB, its release within about 5 dB over its first 60 dB. Like Choir Aahs, it follows the velocity and not CC2. Its onset, a 240 ms attack, is the same on every key; Choir Aahs's varies from sample to sample, and is within 2–3 dB (rms over the first 400 ms) of such an attack on most keys, but much faster on the samples of E4 and C5 (11 dB louder at 40 ms on C5). Choir Eehs and Choir Uuus are MS Basic Aahs singing "ee" and "oo".
- **Export SF3** writes the file, with its one preset at the program number beside it, and its samples compressed to Ogg Vorbis (quality 5), which takes about a second.

## Putting an exported instrument into the choir app

The choir app fetches `media/soundfont/<program>.sf3` for each General MIDI program. The programs in `OWN_PROGRAMS` of `site/src/lib/instruments.ts` are its own instruments, which `site/scripts/soundfont.ts` doesn't write from MS Basic: 54, Practice Synth, is one.

1. Export with program 54 to replace Practice Synth, or with another program that MS Basic's files in `media/soundfont/` don't use.
2. Copy the file to `../media/soundfont/<program>.sf3`.
3. For a new program, add it to `INSTRUMENTS` and `OWN_PROGRAMS` in `site/src/lib/instruments.ts`.

## How it works

- **Patch:** `src/lib/patch.ts` has the parameters; `src/lib/build.ts` makes the sound bank from them with spessasynth_core's `BasicSoundBank`, one preset of two instruments (tone and attack), with a zone for every few keys (Key spacing) from A1 to C7. Each zone's samples are made for its middle key, so the EQ, the vowel and the contour stay at the same frequencies on every key.
- **Tone samples:** each is a spectrum turned into a signal by an inverse FFT of a power-of-two length (Loop), so the loop repeats seamlessly: every partial, and the breath noise, falls on a bin of the FFT. The fundamental is then off by up to half a bin (0.24 Hz with the defaults), which the sample's pitch correction makes up for, to the nearest cent.
  - The harmonics' levels come from the tilt, the even harmonics' level and the drawn offsets, then the EQ, the vowel and the spectral contour. Each key is as loud at full dynamics: the harmonics are normalized to the same power, as the synthesizer's low-pass filter lets them through, so that the timbre controls don't change the loudness. That leaves the Level to set it.
  - **Ensemble:** each harmonic is split into Voices copies, each detuned at random within the Detune; the fundamental's within the Fundamental detune, and not at all at 0. The upper harmonics beat at unrelated rates, which shimmers while the loudness stays within about 2.5 dB (measured over 250 ms). The fundamental's copies beat into a throb of the whole note. Choir Aahs's fundamental does too: its level varies by 2–3 dB (standard deviation in 171 ms windows), which 15 to 25 cents with seven voices comes close to; with three voices the throb is deeper, up to 5 dB. Copies that fall on the same bin of the FFT, as small detunes on low keys do, become one partial of their power together, so that a key's level doesn't depend on how their random phases add up.
  - **Stereo width:** above 0, each zone has a left and a right sample, panned apart by the width, each with its own detuned copies and breath noise, so that the two sides beat differently. A partial without copies, like the fundamental, is in both, a quarter period apart. Then the sides add up in power like unrelated signals, at any width, and nothing cancels when they're mixed to mono. Each side is 3 dB softer, since spessasynth pans at constant power. Choir Aahs is two recordings panned hard left and right.
  - **Aperiodic noise:** noise between the harmonics, shaped like them (between two neighbours along the logarithm of their power), at a level against them that changes per octave of key and per octave of frequency. It is what Choir Aahs has between its harmonics: its noise falls by about 12 dB per octave of key and rises against the harmonics by about 6 dB per octave of frequency (fitted over its keys from E2 to G5, 5.6 dB rms). The breath noise, in a fixed band, is a different thing, for flutes and breathy tones.
  - **Spectral contour:** dB at third octaves from 50 Hz to 12.7 kHz, in between along the logarithm of the frequency, on the harmonics and the breath noise; one for E2, one for A#3 and one for E5, and each zone mixes the two on either side of its key. Several registers because Choir Aahs's high samples have their formants elsewhere than its low ones: one contour for all keys left its high keys further from Choir Aahs than no contour. On the keys that Match doesn't fit (Choir Aahs's sample roots, from F#2 to A5), three registers leave the default patch 5.0 dB rms from Choir Aahs, two 5.5, four 4.8; contours at sixth octaves fit the fitted keys closer (3.6 dB against 3.9) and the others no closer. **Match** (`src/lib/measure.ts`, in `match-worker.ts`) renders notes of the instrument and of the patch at mf on every third key from E2 to G5, one in each of Choir Aahs's zones, measures each harmonic's power from 1.5 s on, and fits the change to the contours by least squares over the harmonics that the instrument has above its noise, with an offset of its own for each key (each key's tone is normalized anyway), a little smoothness between neighbouring frequencies and a weak tie between the registers. Since the contour adds in dB before the synthesizer's filter, one fit is about as good as the fit expects: for the default patch against Choir Aahs, 8.6 dB rms per harmonic before, 3.1 as fitted, 3.7 measured again. What's left is mostly detail from harmonic to harmonic; on the keys between the fitted ones it is more (5.0 dB, up to 6.9 on D#4), perhaps because Choir Aahs plays three keys from each of its samples, whose formants move with the key. The fit is made at mf only: at other dynamics, the tone's filter and the instrument's move differently, by an amount not yet measured.
  - **Vowel** (`src/lib/vowel.ts`): the gain of a vocal tract, a cascade of five resonators at the vowel's formant frequencies and bandwidths (Csound's table; the bandwidths times the Formant width), against the same for a neutral vowel, the geometric mean of the five vowels' formants, in dB times the amount. The formants are a bass's on E2, a tenor's on A#3 and a soprano's on E5, and in between along the logarithm of the frequency on the keys between. In a cascade the formants' levels follow from their frequencies and bandwidths, so at amount 1 the vowels differ by as much as a vocal tract's do. Chimera's physical model of a vocal tract (`~/code/chimera-vocal-synth`) checks this: given its own formants, the cascade predicts how its sung "ee" and "oo" differ from its "ah", per harmonic on every third key from E2 to G5, within 4.4 and 6.1 dB rms, where they differ by 14.0 and 11.1 dB (best at amount 1 and width 1.5). Its vowels themselves are spoken American English: its "oo" has F2 at 1000 Hz, against 600 Hz in Csound's sung table, even in its sung posture, so the table is Csound's.
  - Match fits the contour with the vowel as it is: it can't tell from Choir Aahs where its formants are. Fitting a shift of the formant frequencies per register along with the contour brought the fit 0.1 dB nearer, since the contour takes up the difference either way.
  - MS Basic Aahs has the filter off: one at a harmonic follows the key, unlike a vocal tract, and on low keys it took away the 2–3 kHz of "ee", which the normalization made up for by more than the samples could reach. Matched without it, it is as near Choir Aahs.
- **Attack samples:** decaying sines, each higher harmonic decaying faster (Damping), optionally stretched like a piano string's partials (Inharmonicity), plus white noise through a band-pass with an exponential decay. They play once, without a loop.
- **Levels:** samples are stored at a peak of 0.9, and each zone's `initialAttenuation` brings them to their level (spessasynth, like E-mu's hardware, applies 0.4 of it). A level beyond what a sample at full scale can reach is reported as too loud. Level 0 dB is calibrated to about the loudness of MS Basic's Choir Aahs at mf (`npm test` prints both).
- **Dynamics:** the tone's instrument replaces the default velocity-to-volume modulator with one of amount 0, and adds CC2 to volume (concave, like the velocity's) and CC2 to the filter cutoff, which makes soft notes darker. The attack's instrument keeps velocity to volume, with its own range, and velocity to the filter. With "Tone follows: velocity", the tone uses the velocity like an ordinary instrument. CC2 is 0 until a MIDI file sets it, which silences a tone that follows CC2: MuseScore's files set it for every note, and the keyboard sends it before each note.
- **Onset:** the modulation envelope makes the tone brighter (Onset bright) and optionally flat (Scoop) at the start of each note, and decays in the Onset time.
- **Playing:** the page plays with the choir app's synthesizer (`../site/src/lib/synth.svelte.ts` and the files it uses), so it plays exactly as the choir app would. `src/lib/designer-synth.ts` arranges a piece with the vocal parts on the designed instrument, and uses what the synthesizer offers beyond the choir app's needs:
  - a bank made in memory (`addBank()`), which replaces a bank under the same id without resetting the synthesizer: it swaps the bank in spessasynth's sound bank list and calls `refreshPresets()`, so the channels keep their controllers. Adding a bank with `addSoundBank()` resets all controllers and stops all notes, so the engine seeks again after adding a bank while playing, which restores the score's controllers;
  - MIDI messages played at once (`send()`), for the keyboard, on channel 16;
  - a program's samples loaded for given notes (the keyboard's), not only the score's.
- **Building:** `src/lib/build-worker.ts` builds, writes the SF2 file and reads it back, so that the page plays the file as written, and renders the preview note with a `SpessaSynthProcessor` of its own. The page plays the samples uncompressed: compressing them would make each rebuild about half a second slower. Export writes the file again with its samples compressed (`src/lib/vorbis.ts`): browsers have no Vorbis encoder, so it uses libvorbis compiled to WebAssembly (`wasm-media-encoders`), loaded only when exporting. Decoded, the samples keep their lengths and loops; `npm test` checks that, and that the SF3 file plays as loud as the SF2. `src/lib/builder.svelte.ts` keeps one build running at a time and drops all but the newest waiting patch. Samples are cached by the parameters they depend on, so most changes don't synthesize anything.

## Limitations

- **Compression is heard only in the export:** the page plays the samples as 16-bit PCM (about 4 MB with the defaults), the exported file has them in Ogg Vorbis (0.67 MB, against 0.65 MB for MS Basic's Choir Aahs). How the compression sounds, around the loop points in particular, has only been measured, not listened to: the error at the start and end of a loop is a few dB above the error in its middle, and the step across the loop point no larger than the steps elsewhere.
- **Loops are static:** apart from the ensemble's shimmer, vibrato and tremolo, each tone sample repeats exactly every Loop seconds.
- **Other vowels are a model's:** Choir Eehs and Choir Uuus are untested against a choir singing them; MS Basic has no other vowel of the same choir (its Voice Oohs is a few samples, each transposed over an octave or more, so its formants move with the key). The contour that Match fits keeps whatever of Choir Aahs's "ah" Csound's "a" doesn't explain, such as a peak near 400 Hz on low keys, and the other vowels keep it too. The formant table is Csound's, of unknown origin, with five voices of which three are used.
- **Unisons** of several parts on the same key start the same sample at the same place, so they add up exactly rather than like separate voices.
- **Untested:** how the instrument sounds to a singer following it; the tests check levels and modulators, not musical usefulness.
